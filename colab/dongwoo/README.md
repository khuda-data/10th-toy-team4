# 도착 예정 버스 잔여좌석 예측 — 김동우

팀 수집 서버의 실측 데이터로 "버스가 목표 정류장에 **도착해 문을 열기 직전**의 잔여좌석"을
예측한 작업입니다.

전체 과정과 결과는 **[작업기 리포트](./reports/work_log_report.html)** 에 정리했습니다.
(브라우저에서 열어보려면 파일을 내려받아 열거나, GitHub 미리보기 대신 raw 파일을 저장해서 여세요.)

## 결과 요약

테스트: **2026-08-18(화)** 하루, 17,567 도착사건. 학습·검증에 한 번도 쓰이지 않은 날.

| 방법 | 전체 MAE | 저잔여(≤5석) MAE | ±3석 적중 | 만차 F1 |
| --- | ---: | ---: | ---: | ---: |
| 앱 현재값 그대로 (기준선) | 6.721 | 17.861 | 51.1% | 0.237 |
| 최근 추세 연장 | 7.660 | 12.750 | 46.1% | 0.210 |
| 과거 평균 | 5.229 | 16.494 | 50.0% | 0.000 |
| 구간 소진량 통계 (ML 없음) | 4.835 | 11.078 | 55.0% | 0.378 |
| HistGBM (절대값 타깃) | 2.670 | 6.089 | 71.3% | 0.437 |
| LightGBM (변화량 타깃) | 2.615 | 5.808 | 71.8% | 0.423 |
| **LightGBM + 저잔여 가중 (최종)** | **2.652** | **3.739** | **72.0%** | 0.481 |
| **만차 전용 분류기** | — | — | — | **0.592** |

- 기준선 대비 오차 **61% 감소**(6.721 → 2.652석), 저잔여 구간은 **79% 감소**(17.861 → 3.739석)
- 실제 만차 버스 10대 중 **7대**를 미리 포착(Recall 0.708, Precision 0.509)

## 라벨 정의

GBIS `stateCd`는 `0`=운행중, `1`=정류장 도착, `2`=정류장 출발입니다.
사용자가 정류장에서 마주치는 좌석은 **태우기 전**인 `stateCd=1` 시점입니다.

| 등급 | 정의 | 건수 |
| --- | --- | ---: |
| A | 목표 정류장 방문 중 `stateCd=1` 첫 관측 좌석 (직접 관측) | 100,330 |
| B | A 누락 시, 같은 운행 직전 정류장의 `stateCd=2` 출발 좌석 (10분 이내) | 85,522 |

> **B등급 누수 주의**: B의 정답은 직전 정류장 출발 좌석 그 자체입니다.
> 따라서 그 정류장 스냅샷(`stop_gap==1`)을 입력으로 주면 정답을 그대로 복사하게 됩니다.
> 이 조합 **69,237행**을 명시적으로 제거했습니다. 각자 파이프라인에서도 확인이 필요합니다.

## 평가 지표

- **event-balanced MAE** — 도착 사건마다 먼저 평균을 낸 뒤 그 평균들을 평균합니다.
  상류 스냅샷이 많은(=어려운) 사건이 과대표집되는 것을 막습니다.
  같은 모델이라도 행 단위로 계산하면 2.83, 사건 단위로는 2.65가 나옵니다.
- **저잔여 MAE** — 실제 도착 좌석이 5석/10석 이하인 사건만.
- **만차 분류** — 실제 0석에 대한 Accuracy / Precision / Recall / F1.
- **within-3 / within-5** — 오차가 3석/5석 이내인 비율.

## 분할 (날짜 기준, 시간 누수 차단)

| 구분 | 날짜 | 도착사건 |
| --- | --- | ---: |
| 학습 | 2026-08-03 ~ 08-17 | 140,420 |
| 검증 | 2026-08-14 (금) | 18,765 |
| 테스트 | 2026-08-18 (화) | 17,567 |
| 제외 | 2026-08-19 | 오전까지만 수집돼 퇴근 러시 누락 |

> **연휴 주의**: 8/15 광복절이 토요일이라 **8/17 월요일이 대체공휴일**입니다.
> 평일 월요일의 저잔여 발생률 3.57% 대비 8/17은 **0.26%** (14배 차이).
> "마지막 N일 = 테스트"로 나누면 출퇴근 모델을 연휴로 평가하게 되고,
> 만차가 거의 없어 **만차를 전혀 못 잡는 모델도 좋아 보입니다.**

## 주요 설계 결정

1. **변화량(delta) 타깃** — 절대 좌석수가 아니라 "현재 대비 몇 석 줄어들까"를 학습하고
   마지막에 현재 좌석을 더합니다. 현재 좌석은 이미 아는 값이므로 모델이 어려운 부분에 집중합니다.
2. **손실함수 = 평가지표** — 평가가 MAE이므로 `regression_l1` / `absolute_error`를 씁니다.
   학습 가중치도 평가와 동일한 사건 균형으로 맞춥니다.
3. **회귀와 만차 분류 분리** — 만차는 전체의 1.3%뿐이라 회귀가 무시합니다.
   분리하면 회귀는 저잔여 MAE만 보고 최적화할 수 있습니다 (F1 0.481 → 0.592).
4. **저잔여 4배 가중** — 전체 MAE를 0.054석 희생하고 저잔여 오차를 **38% 개선**합니다.
5. **연휴 0.3배 가중** — 연휴를 버리지 않되 평일 신호를 희석시키지 않게 발언권을 낮춥니다.

## 직접 설계한 피처: `expected_drop`

남은 구간의 정류장들에서 평소 몇 석씩 빠지는지를 학습기간 통계로 계산해 누적합으로 만듭니다.

```
expected_drop = cum[target_seq] - cum[snap_seq]
```

이 값 하나만으로 예측해도 **MAE 4.835석**이 나와 과거 평균(5.229)이나 추세 연장(7.660)을 앞섭니다.
학습된 모델의 퍼뮤테이션 중요도에서도 `snap_seats`, `hist_seat_stop_hour`에 이어 **3위**입니다.

## 실패한 시도 (기록용)

- **앞차 정보 피처** — "앞차가 만석이면 승객이 이월돼 다음 차가 빨리 찬다"는 가설.
  저잔여 MAE가 평일 3.903 → 3.959, 연휴 5.319 → 5.326으로 **악화**되어 폐기했습니다.
  배차 3~20분 사이 새로 도착하는 승객이 이월 승객보다 많아 효과가 묻히는 것으로 보입니다.
- **연휴 데이터 단순 추가** — 학습 사건을 65% 늘렸더니 평일 저잔여 MAE가
  3.754 → 3.832로 **악화**. 분포가 다른 데이터는 신호를 희석시킵니다.
  가중치 0.3배로 낮춰 넣는 방식으로 해결했습니다.

## 팀에 제안

모델 비교가 성립하려면 아래 4가지를 통일해야 합니다. 현재는 조원별로 전부 다릅니다.

1. **예측 거리** — 1정거장과 20정거장은 다른 문제입니다. 같은 모델도 거리만 줄이면
   MAE가 2.83 → 0.57로 5배 좋아집니다. (회의록 문제 정의는 "5 정거장 전")
2. **정답 정의** — 태우기 전(`stateCd=1`)인지 후(`stateCd=2`)인지.
3. **테스트 날짜** — 그리고 **연휴(8/15~17)는 테스트에서 제외**해야 합니다.
4. **채점 방식** — 사건 단위(event-balanced) vs 행 단위.

참고로 **1정거장 예측은 기준선(MAE 0.440)이 학습 모델을 이깁니다.**
직전 정류장 출발 좌석과 다음 정류장 도착 좌석 사이에는 승하차가 없기 때문입니다.
